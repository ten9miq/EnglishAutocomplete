# 実アプリ・IME・共存の手動試験

下表には実アプリでの未検証項目を含む。別プロセスの専用Win32 Edit fixtureによる自動試験と区別する。個人文書ではなく新しい空の試験用文書を使い、最初はLearning=0で確認する。

## ブラウザーの入力直後の選択状態

- Chrome / BraveのURL欄、ChatGPTのチャット入力欄、GitHubのGo to file欄で、`confi`を手入力して候補表示を確認する。DOMのfillは実キー入力の代わりにしない。
- 全選択からの置換直後など、UIAが選択状態を一時的に更新しきれていない間は候補・候補キーを無効にする。350ms以内に新しい安全な読み取りに成功すれば、観測した先頭文字を失わず候補へ戻ること。
- 選択範囲が残る場合、readonly、password、フォーカス移動、350msを超える取得失敗では確定しないこと。未選択のEnterはページ送信・URL移動へ渡るため、表示だけの試験では押さない。
- ChatGPTなど深いWeb入力欄では、旧32要素を超えても64要素・200ms以内に同じ前面ウィンドウの祖先を確認できれば扱う。隣のタブ・別ウィンドウへ移動した際の候補破棄も確認する。
- Go to fileなどの仮想フォーカスでは、候補項目をUIA focusが指した状態でも入力欄の可視キャレット・ControllerFor関係が確認できれば候補を表示すること。候補項目をクリックして実フォーカスを移す、キャレットを消す、別入力欄へ移す、readonly/password/選択ありにする場合は停止すること。確定前には新しい入力欄内の本文を再照合し、GitHubの標準候補を開かず単語の語尾だけ追加されること。
- 専用ChromeのURL欄は変更前に利用者の手入力で候補表示・確定を確認。通常BraveのURL欄は変更前に候補非表示と入力追跡の欠落、修正後に候補表示を確認した。ChatGPTの入力欄も階層上限の修正後に候補表示を確認済み。送信を避けるためChatGPTのEnter確定は未試験。Go to fileは最終修正後に候補表示・Tab青選択・Enter確定を利用者の実キーで確認し、診断ログもselected=1とCommitCountが0→1→2へ増えたことと一致した。

## 対応入力欄での手順

1. 新規の試験用文書、ENG、Learning=0で開始。既定のMinLength=2で`c`では候補なし、`co`まで入力すると初期5候補が表示されること。続けて`confi`にし、候補が更新されてフォーカスが入力欄に残ることを確認。
2. Ctrl+Alt+Down/Upで選択表示が変わること。Ctrl+Alt+Spaceで既存`confi`を残した語尾だけが入ること。改行・Tab・空白の自動挿入がないこと。
3. Tabで選択開始後、数字2（通常列とテンキー両方）で2番の候補を確定。選択前の数字は文字として入ること。表示件数より大きい番号キーは元のアプリへ渡ること。Escで非表示、既存文字は残ること。
4. BSで入力文字と候補が短くなること。通常のDelete、左右/Home/End/PageUp/PageDown、選択操作、削除用×以外のクリック、ホイールでは候補を閉じること。
5. コピー、貼り付け、切り取り、Undo/Redo、アプリ側の自動補正で古い候補を確定できないこと。入力済み単語の中間位置では補完しないこと。
6. 入力中に同じ窓の別欄/別アプリへ切り替え、確定キーを押しても前の欄へ文字を送らないこと。
7. Tab/Enterを無効のまま通常操作を確認。その後試験アプリだけで明示有効にし、候補がない時は通常操作、候補がある時は補完だけになることを確認。
8. `COM`/`Com`/CamelCaseを入力し、入力済み表記を削除せず適切な語尾だけが追加されること。
9. 日本語IMEへ切り替えて未確定入力を作り、英文候補も学習も生じないこと。ENGへ戻して新しい単語から再開すること。
10. MS-IMEをONの半角英数にして、TextEditPattern対応のRichEdit等で`confi`を入力。候補表示と語尾追加を確認する。IME OFFとして照会される「A」はONの半角英数試験に含めない。標準Editなど照会できない欄では候補が出ないこと。
11. 候補表示中にマウスでひらがな・全角英数へ変更し、確定キー・Tab/Enter/Escが元のアプリ/IMEへ渡ること。半角英数のまま未確定入力/再変換を作れる場合も、候補確定・学習が止まること。取消後は新しい単語から再開すること。
12. 候補表示中にIME OFF→ON、mode 0→16等の許可状態間の変更を行い、変更前の候補を確定できないこと。照会エラー/応答遅延/フォーカス喪失時も補完せず、本文・クリップボードを変更しないこと。

### 初期5→9候補・IME風キー操作（2026-11-09変更）

- IME OFFで`confi`を入力し、初期5件が未選択（背景ハイライトなし）であること。最初のTab/↓で1件目、その後は次候補へ進むこと。5番目を選んだその表示から9件へ展開すること。4番へ戻っても9件を維持し、通常文字・取消・次の語で初期5件へ戻ること。未選択のShift+Tab/↑は9件目へ移り同時に展開し、その後は前候補へ進むこと。
- 候補表示中・選択モード中でもSpaceとShift+Spaceで普通の空白が入力され、候補を選んだり確定したりしないこと。空白入力で候補と選択モードが終了すること。Ctrl+Alt+Spaceの明示確定は維持する。
- 選択開始前の数字は文字入力。Tab後の数字1～5・テンキー1～5で対応候補の語尾だけが入ること。展開前の6～9は文字入力、展開後は候補確定になること。IME ON・ImeStyle=0・対象外欄では数字を横取りしないこと。
- 選択開始前のEnterは入力先へ渡り、選択モード中だけ候補の語尾を追加すること。確定後は選択モードを終了し、改行/送信を重ねて実行しないこと。
- 確定Enterを長押し/リピートしても確定は1回・改行0回になること。キーを離してから別にEnterを押すと通常の改行/送信だけになること。短い押下でkeyupが先に処理されてもEnterが効かなくなる状態を残さないこと。
- Esc・空白・通常文字・左右移動・クリックで選択を終了すること。候補なし・対象外・キー無効アプリではTab/矢印/Enterを横取りしないこと。Space/Shift+Spaceは状態に関係なく候補操作へ割り当てないこと。Ctrl+Alt+Tabを登録しないこと。
- IME ONでは半角英数を含めスクリプトの候補と選択を停止し、MS IME等のSpace/Tab/矢印/Enterが働くこと。IME ONへ切り替える前の候補を確定できないこと。
- `ImeStyle=0`のアプリではIME風キーを使わず、既存の明示ショートカットだけになること。

状態遷移92項目、専用Win32 Editで実OnChar/実ホットキー28項目（初期5件・5番で9件・Tab→数字3/9・Enterリピート抑制）を自動確認。後続のChrome専用localhostフォームの手入力試験では、候補表示・Tab→3・Tab→Enter・未選択Enterを確認した（docs/VALIDATION.md参照）。初期5→9行の実表示、任意のWebアプリ、合成OSキー自動試験、Codexでの新UI・新キーは未確認。

## 学習と安全

### 辞書管理画面

- 本体のトレイメニュー「辞書管理画面を開く」から別プロセスの管理画面が開くこと。閉じても本体と補完が動作を続けること。本体と同じAHK v2実行ファイルを使い、空白や日本語を含むインストール先でも起動できること。
- `ManageDictionary.ahk`を引数なしで起動し、「使い方」と「辞書管理画面を開く」ボタンが表示されること。閉じると管理ツールが終了し、常駐本体は動作を続けること。`--help`も同じ表示、`--gui`は管理画面へ直接入ること。使い方だけでは個人DBを作成しないこと。
- 試験用の個人DBで管理画面を開き、検索・手動登録/自動学習/禁止の絞り込み・100件単位のページ移動を確認する。単語・回数・最終使用日時が読め、行選択で「操作する単語」が一致すること。日本語表示と100～200% DPIの表示は実機で確認する。
- `MyInternalTool`や`config.toml`を登録し、表記更新・禁止・禁止解除・再登録を確認する。禁止の確認文に回数と手動登録状態も消えることが表示されること。不正な単語は書き込まれないこと。
- 配布辞書へ切り替えて英単語と日本語訳で検索する。配布辞書の行を選んで禁止すると新しい補完検索から非表示になり、禁止解除すると戻ること。管理画面は配布DBを書き換えないこと。「個人データ削除」後も配布辞書の語は残ること。
- 削除・頻度初期化・全消去で確認ダイアログの既定が「いいえ」になり、取消時はDBが変わらないこと。頻度初期化は手動登録と禁止を保持し、全消去は個人データだけを消すこと。実データで破壊的な操作を試さないこと。
- 本体と同時に起動し、本体の登録/学習が「再読込」で表示され、管理操作が本体の新しい候補検索へ反映されること。本体・他のAHK・IMEを終了/再起動しないこと。DBロック/破損ではエラーを表示し、成功したように見せないこと。

### 個人辞書のCSVエクスポート・インポート

- 試験用DBに手動登録・学習語・禁止語を作り、「エクスポート（CSV）」で日本語を含む保存先へ保存する。検索や絞り込み中・配布辞書表示中でも、個人辞書全件が保存されること。保存先の選択取消ではファイルを作らず、既存CSVの上書き拒否では元のファイルが残ること。拡張子なしで指定して`.csv`を補う際も既存CSVを無断上書きしないこと。
- 別の試験用DBへインポートし、表記・回数・最終使用日時・手動登録・禁止が一致すること。既定では既存の同名語を保持し、上書きチェック時だけCSVの値で置き換わること。CSVにない語は残り、回数を加算しないこと。確認ダイアログには件数と既存語の扱いが表示され、取消では書き込まないこと。
- 不正UTF-8、列数/見出し違い、無効語、負の回数、状態が0/1以外、同一語の大小文字違い重複、8MiB超、10000語超、DBロック/書込失敗で全体を拒否し、一部だけ反映しないこと。実データへ故意に不正CSVを入れないこと。
- 常駐本体を維持したまま、取込後の新しい候補検索から登録・禁止が反映されること。設定と配布DBが変わらないこと。100～200% DPIで新しいボタン・チェック欄・結果件数が読めること。

`tests/transfer.ahk`は一時DBでCSVの往復、既存保持/上書き、メタデータ保持、入力検証、容量制限、DB書込失敗時のロールバック、取消分岐、検索に依存しないGUIの入出力処理を検証する。ファイル選択ダイアログ・トレイ実操作・異なるDPIとは区別する。
